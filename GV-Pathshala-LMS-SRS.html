1. Introduction

1.1 Purpose

This document specifies the requirements for GV Pathshala, a web-based learning management system (LMS) with built-in AI assistance. It is written for developers, testers, project supervisors and anyone who needs to agree on what the system must do before it is built.

1.2 Scope

GV Pathshala lets an institution publish courses, enroll students, deliver lessons, assess learning and track progress. Four AI features sit on top of that core: a course tutor chatbot, a quiz and feedback generator, a learning analyzer and a course recommender.

Out of scope for release 1.0: native mobile apps, live video classes, online payments, offline use and languages other than English.

2. Overall description

2.1 Product perspective

GV Pathshala is a new, self-contained web application. A browser-based client talks to a server through a REST API. The server stores data in a relational database, keeps files in object storage and calls an external AI model service for the AI features. The AI features are isolated in their own module so the LMS keeps working if the AI service is unavailable.

2.2 Product functions

  • Account management with three roles
  • Course authoring: modules, lessons, quizzes and assignments
  • Catalog, enrollment and progress tracking
  • Automatic quiz grading and manual assignment grading
  • Announcements, discussion and notifications
  • Certificates and course reviews
  • Administration and reporting
  • AI tutor, AI quiz and feedback generator, AI learning analyzer and AI recommendations

2.3 User classes

User classDescriptionMain needs
StudentLearner enrolled in one or more courses. Technical skill varies.Find courses, learn at their own pace, get help quickly, see progress and grades.
InstructorTeacher who creates and runs courses.Build content quickly, grade fairly, see who needs help.
AdministratorStaff member who runs the platform.Manage users and courses, see usage, keep the system safe.
AI serviceExternal model service called by the server (system actor).Receive minimal, well-formed requests and return text.

2.4 Operating environment

  • Client: current versions of Chrome, Edge, Firefox and Safari on desktop, tablet and phone
  • Server: Linux, Node.js 20 or later (or equivalent), PostgreSQL 15 or later with a vector extension (pgvector)
  • Storage: S3-compatible object storage for videos, PDFs and uploads
  • AI: a hosted large language model API and an embedding model API

2.5 Design and implementation constraints

  • The AI provider key must stay on the server.
  • Uploaded files are limited to 20 MB each (videos are uploaded separately to object storage).
  • The project must be completed within 10 weeks by a small team.
  • Personal data handling must follow India's DPDP Act 2023.

2.6 Assumptions and dependencies

  • Instructors supply the course material that the AI tutor learns from.
  • The AI provider's API is available and its pricing stays within the project budget.
  • Students have a stable internet connection.
  • An SMTP service is available for email.

7. System architecture

7.1 Components

ComponentResponsibility
Web clientSingle-page application. Shows courses, lessons, quizzes and the AI panels.
API serverAuthentication, business rules, grading, notifications. Exposes the REST API.
AI service moduleRetrieval, prompt building, safety rules, output checks and calls to the AI provider.
Background jobsIndexes course content, calculates analytics, writes weekly summaries, sends emails.
DatabasePostgreSQL for records and pgvector for content embeddings.
Object storageVideos, documents and uploads.

7.2 AI tutor request flow

  1. The student sends a question from a lesson page.
  2. The server checks the session, enrollment and rate limit.
  3. The question is converted to an embedding and the 5 most similar content passages from that course are retrieved.
  4. If the best passage is below the similarity threshold, the server replies that the answer is not in the course material.
  5. Otherwise the server builds a prompt: fixed rules, the passages, recent chat history and the question.
  6. The AI model writes an answer that must refer to the supplied passages.
  7. The server checks the answer for citations and for integrity-mode violations.
  8. The answer and its sources are stored and streamed to the student.

10. Risks and responsible AI

AI features bring risks that a normal LMS does not have. The design answers them directly: answers come only from course material, people approve AI output that affects grades, and personal data is kept to a minimum.

RiskImpactMitigation
The tutor gives a wrong or invented answerHighAnswer only from retrieved course text, refuse when nothing is found, show sources, label as AI, and review a 100-question test set before release.
Students use the tutor to get graded answersMediumAcademic integrity mode with hints only, and instructor control to switch the tutor off per course.
Student data is exposed to the AI providerHighSend the minimum data, pseudonymise users, check provider terms on training and retention, and keep keys on the server.
Prompt injection through course content or chatMediumTreat inputs as data, give the model no write access, validate outputs and log suspicious requests.
AI costs grow faster than plannedMediumPer-student rate limits, response length limits, caching of repeated questions and a monthly spending cap.
Instructors trust AI drafts too muchMediumDrafts are clearly marked and require explicit approval before they take effect.
Scope grows beyond the time availableMediumBuild Must items first. Treat Could items as optional extras.
